# Agent Memory Governance Benchmark — 条款全文

> 版本：公开草案 v1.1（外发通用版）· 2026-09-30 · 起草：正明（Zhengming）· 英语版：[STANDARD_EN.md](STANDARD_EN.md)
> 核心主张：**记忆治理的杠杆在行为层，不在表示层**——Agent 内部"我记住了/我完成了"的自报信号不作数，标准必须约束**可观测的动作**：写入前过没过闸？该忘的忘没忘住？删的东西有没有人签字？
> 状态声明：本文件是公开规范草案（open standard draft），不是任何官方行业标准。

---

## 0 · 费曼导论：这标准是干嘛的

现在的 AI 像一条金鱼——每次聊天只有几秒记忆（行话叫"上下文窗口"）。于是全行业都在卖一种东西叫**记忆层**：给 AI 外挂一个笔记本，把聊过的事记下来，下次翻开接着聊。

问题不是"有没有笔记本"，而是**笔记本上写的东西对不对、找不找得到、该扔的不扔、该留的不留**。权威基准 LongMemEval（ICLR 2025，UCLA & 腾讯 AI Lab）实测：把"有笔记本的商用 AI"放到长时间连续对话里考，准确率平均掉 30%（S-longmemeval）。

为什么需要一份标准：整个行业都在卖内存条，**却没人定电工标准**。每家都说"我有记忆功能"，但没有一条共同红线回答：记错的东西能不能拦住？该忘的能不能真忘住？删掉的东西去哪了？本标准把这些问题变成 **11 条可机器验证的条款**——每条都带"为什么要有它"（缘由）、"业界权威怎么做"（对照）、"起草方怎么做到的"（证据）。

本标准的独有立场：市面上的方案（Mem0、Zep、MemGPT/Letta）都在比"谁的记性好"——这是**表示层**的竞争。本标准补的是另一半：**行为层的治理**——不管记性多好，"我记住了"这句话本身不作数，要看得见动作。

## 1 · 权威谱系：本标准站在谁的肩上

| 源头 | 年代 | 核心贡献 | 关键事实 |
|---|---|---|---|
| Atkinson–Shiffrin；Tulving | 1968-72 | 人类记忆多重存储模型；情景/语义记忆之分 | 今天所有 AI 记忆分类的祖师爷（S-coala） |
| CoALA（Sumers et al.） | 2023 | 人类记忆三分类系统映射到语言代理 | semantic/episodic/procedural 成为 AI 通用词汇 |
| MemGPT | 2023 | 虚拟上下文管理，OS 分页类比 | "主上下文=RAM，外部存储=磁盘"；现为 Letta（S-memgpt） |
| Mem0 | 2025-04 | 动态"抽取-整合-检索"管线 + 图记忆 | LOCOMO 登顶：LLM-as-a-Judge 相对 +26%，p95 延迟降 91%（S-mem0） |
| Zep/Graphiti | 2025-01 | 时间知识图谱 + 双时间戳 | LongMemEval gpt-4o 60.2%→71.2%（S-zep） |
| LongMemEval | 2024-25 | 行业唯一公共记忆基准：五能力/500 题 | 商用助手持续交互准确率掉 30%（S-longmemeval） |
| 本基准 | 2026-09 | 行为层治理：三道闸 + 五条战略纪律 | 11/11 条款机器可断言，自检器实跑通过 |

谱系读法：前六行回答"怎么把记忆**造**得更好"（表示层），最后一行回答"怎么让记忆系统**守规矩**"（行为层）。两代不冲突。

## 2 · 范围、定义与费曼词典

**适用对象**：跨会话持久记忆层（SaaS / 开源 / 端侧 / 模型内嵌均适用）。

| 术语 | 费曼版（说人话） | 行话与出处 |
|---|---|---|
| 记忆层 | 给金鱼大脑外挂的笔记本 | persistent memory layer |
| 短期/长期记忆 | 桌上的便签（这通电话用）vs 档案柜（换工作还跟着你） | LangGraph：thread 级 vs 跨线程 Store（S-langgraph） |
| 语义/情景/程序性记忆 | 课本知识 / 日记 / 肌肉记忆 | 源自认知科学，经 CoALA 映射进 AI（S-coala） |
| 双时间戳 | 事情**发生**的日子 vs 你**听说**的日子 | Zep：event time T + ingestion time T'（S-zep） |
| 写入闸（T1） | 笔记本不是想写就写——先过安检，拿不出验证凭证不让进 | write gate（本基准首创） |
| 毒样本隔离（T2） | 记错的号码贴封条锁进隔离病房，翻档案永远翻不到 | quarantine registry + 检索过滤（本基准） |
| 不可逆闸（T3） | 碎纸机前必须有人签字 | irreversible operation HITL（本基准） |
| 事故棘轮（T5） | 像驾照扣分：同型错误复发扣双倍，分只加不减 | incident ledger + weighted recurrence（本基准） |
| 轨迹蒸馏（S1） | 每次搞砸后开复盘会，写成操作手册页 | trajectory distillation |

**设计公理**：①无记忆层则 Agent 是无状态服务，跨会话等于失忆；②"写入便宜、读取昂贵"是本末倒置——写入必须贵（过闸），一条坏记忆的读取成本是终身的；③记忆层自己必须有记忆治理（元记忆）——管记忆的规则本身要能被机器检查。

## 3 · 战术层条款 T1-T6（每条 = 机器可断言）

### T1 · 写入闸 —— 未经验收的记忆不得入库

**费曼**：笔记本不是想写就写。任何一条新记忆进门都要出示凭证："这条信息验证过吗？"拿不出验证记录就不许写入——哪怕它看起来很有道理。写进笔记本只要一秒，一条错的记忆会在以后每次翻笔记时被相信一次，错一辈子。

**缘由**：防**脏写入**——记忆系统头号污染源。LongMemEval 把"知识更新"列为五能力中最难类别之一，根因是新旧事实语义相似度几乎一样，向量检索天生分不出谁新谁旧（S-longmemeval）。一旦错误信息无闸写入，下游没有任何检索技术能可靠兜底。Mem0 让 LLM 在抽取阶段决定 ADD/UPDATE/DELETE（S-mem0），但算法把关是概率的，验收把关是确定的：本条款要求一条可追溯的 pass 级验证记录（测试/实勘/盲评）。

**权威对照**：Mem0 抽取-整合两阶段，LLM 充当守门人（算法口径）；LangGraph 区分热路径写入与后台异步写入，讨论的是**时机**而非**资格**（S-langgraph）。本基准差异：把写入从"算法觉得该记"升格为"验证记录允许记"，且判定机器可断言。

**起草方证据**：guard_gate.py I1 端到端实测：无实勘证据的台账条目被拒收，带证据条目放行。

### T2 · 检索闸 —— 毒样本不得出现在任何检索结果

**费曼**：记错的电话号码不能光"标注一下"，要贴封条锁进隔离病房——以后每次翻档案，隔离病房里的东西永远翻不出来。光标"过时"不够：翻档案的机器人看不懂标注，照样把旧地址交出去。

**缘由**：防**毒记忆复活**。LongMemEval 实测"知识更新"类问题中，检索系统频繁把被取代的旧事实当答案交回（S-longmemeval）。Zep 的解法是图谱内边失效 + 时间逻辑判定（S-zep），方向正确但依赖时间戳标注完备性；本条款要求**检索出口的硬拦截**：隔离区登记、解除、审计全程留痕，出口处机器断言。

**权威对照**：Zep/Graphiti 语义子图边随新事实失效（S-zep）；Mem0 图变体冲突解决器保持时间一致性（S-mem0）。本基准差异：图谱内失效 vs **检索出口拦截**是两道不同的闸，后者不信任前者。

**起草方证据**：poison_registry 登记节 + 检索出口拦截实测通过。

### T3 · 不可逆闸 —— 删除/覆盖/外发必须人工审批

**费曼**：碎纸机前必须有人签字。记忆的删除、覆盖、交给第三方都是"纸碎了拼不回去"的事——AI 自己不能做主，必须有真人在按钮上按过手印，且记录跟着操作走，事后能查到"是谁、何时、为什么批准的"。

**缘由**：防两类不可逆事故。**对内**——误删/误覆盖等于资产蒸发，无备份即无回滚；**对外**——记忆数据外发第三方，出了门就收不回。行业实证（结构性风险）：Zep 于 2026-08 转向专有许可、Mem0 将图谱功能移出开源、Letta 整体重构——今天存在 SaaS 里的记忆，明天可能换个许可条款。签约前先测导出路径、外发默认上闸，是唯一安全的姿势。

**权威对照**：MemGPT 的 `core_memory_replace` / `archival_memory.insert` 让 LLM 自行编辑记忆（S-memgpt）——自管能力也正是失控面：无人工确认环节。本基准差异：编辑自由，不可逆操作受限（HITL 闸）。

**起草方证据**：push_preflight（无审批拒绝放行）+ 对外发送状态机（无授权记录的发送请求即拒收）双通道实测通过。

### T4 · 质量评分与熔断 —— 坏记忆复利必须有报警器

**费曼**：给每条记忆打"可信分"，像体检指标。分滚动平均（最近表现权重高），一路往下掉或跌破警戒线就拉警报。注意：**报警器只能报警，不能自动杀记忆**——杀不杀由人决定，因为"分低"可能是记忆坏了，也可能是打分的尺子坏了。

**缘由**：防**坏记忆复利**——记忆规模越大，脏记忆拖累检索质量的效应越明显（S-lme-scores）。Mem0 的承重前提是"抽取并只保留显著事实即可保全上下文"，但抽取质量滑坡时系统自己看不见。EMA 斜率恶化 + 低水位双信号是最小代价的探针。

**权威对照**：行业主流无公开的条目级质量评分机制；Zep 用置信度/上下文字段更新边（S-zep）是最近似先例。本基准差异：条目级 EMA + **预警非判决**（熔断决策留人工，防"自动遗忘"误杀）。

**起草方证据**：memory_governor.py 4/4 断言：EMA 斜率恶化与低水位双通道检出。

### T5 · 事故棘轮 —— 犯错要扣分，同型复发扣双倍

**费曼**：像驾照扣分制：犯一次错扣一次分；一年内再犯同一种错扣双倍——重复犯说明上次根本没修好。总分从 100 往下扣，**扣分只认事故记录，不认自我检讨**。这是全标准最不客气的一条：它假设系统会粉饰自己，所以只信台账。

**缘由**：防**自评通胀**。核心实证：Agent 自报"我完成了/我改好了"的内部信号在长会话中对行为无因果驱动——自我评估会系统性漂移成自我表扬。行业对照：LongMemEval 显示商用系统持续交互掉 30%（S-longmemeval），但没有一家厂商公布自己的事故率——事故记账在行业里是空白点。

**权威对照**：行业无公开先例；学术侧近亲是 SWE-bench 式回归测试——但那是"考题"口径，本条款是"病历"口径。本条为**首创条款**，判定规则公开可复现。

**起草方证据**：incident_ledger.py：当前推定分 94/100（2 宗 P2 实录，第二宗同型复发双倍扣 −4）；被闸拦住的未交付 bug 不计——台账只记漏网事故。

### T6 · 原始转录为主记录源 —— 加工品之外，原件必须永存

**费曼**：摘要、笔记、图谱都是"翻译出来的二手货"，翻译会丢东西。所以**原件（一字不差的聊天记录）必须永远留着**，且放在换个系统还能重新读进去的格式里——哪天发现笔记抄错了，还能回原件核对。

**缘由**：防**信息损失**与**供应商锁定**。信息损失证据：递归摘要的失败模式可预测——"人名/数字/引语往往活不过几轮摘要，且模型在知道用户会问什么之前就被迫丢弃了信息"。供应商锁定证据见 T3。LongMemEval 三阶段框架（索引→检索→阅读）同样以原始会话为索引输入（S-longmemeval）。

**权威对照**：Zep 情景子图官方明确"此层不做任何有损转换，保原始记录为 ground truth"（S-zep）；MemGPT recall memory 存全对话史（S-memgpt）。本基准差异：把"存原件"从实现选择升格为**强制条款**，并加上"签约前先测导出路径"的采购动作。

**起草方证据**：三层记忆架构：原始日志（append-only）→ 治理摘要（限长）→ 归档（30 天蒸馏），原件永不覆盖。

## 4 · 战略层条款 S1-S5

### S1 · 轨迹蒸馏 —— 失败是资产，复盘要变成操作手册

**费曼**：搞砸不丢人，白砸才丢人。每次事故之后开复盘会，把"什么症状→什么原因→怎么修的→下次怎么防"写成手册页；**同一种砸法出现两次，这条手册就升格为强制规程**。

**缘由**：防**同型事故复发**与"优化压力指错方向"。传统 RL 用外部奖励优化，模型学会的是绕过评估而非填补能力缺口；轨迹蒸馏把优化压力指向技能库本身。权威背书：LongMemEval-V2（2026-05）把"环境坑（Environment Gotchas：已知失败模式与绕行方案）"列为 agentic 记忆五大能力之一（S-longmemeval-v2）——"记住失败"已成行业公认的一等公民，本条款给出工程实现。

**权威对照**：行业实现侧无公开的"事故→模式卡自动升格"管线。本基准差异：升格判据机器可断言（同型 ≥2 宗自动进规程），且对真实台账实测时**不因想出数字而放松判据**。

**起草方证据**：trajectory_distiller.py：真实台账 2 宗 P2 经相似度判据判定机制不同型，留观察池**不硬凑升格**。

### S2 · 行为层意图对账 —— 自报"完成"不算完成

**费曼**：孩子说"我作业写完了"不算数，作业本翻开来一页页对才算数。任务开始时先列清单（要交付什么、验收标准是什么），收尾时逐条对着产物核——清单上有而产物里没有的，就是"空头支票"。

**缘由**：防**意图与行动断裂**。长会话中 Agent 的意图表示与其后继行为零相关是可复现现象；思维链里写"我应该先验证"与实际是否验证不相关。行业旁证：LongMemEval 把拒答（abstention）列为五能力之一——"知道边界并正确说不知道"本身就是对"自报状态不可信"的基准级确认（S-longmemeval）。

**权威对照**：行业无对等条款：主流记忆系统管理"用户的事实"，不管理"Agent 对自己任务的承诺"。概念近亲是需求追溯矩阵（requirement traceability），本条款把它搬进记忆治理。**首创条款**。

**起草方证据**：intent_drift.py 4/4 断言：对齐 / 整条漂移 / 空头支票（意图条目在产物中缺失）/ 未立案拒收。

### S3 · 有效性 A/B 预注册 —— "有记忆"管不管用，考试说了算

**费曼**：新药上市前要做临床试验，而且**试验方案要在招病人之前写好锁进抽屉**——多少人、怎么分组、什么算有效，先定死再开跑；不然事后总能从数据里"挑"出一个好看的结论。

**缘由**：防两类虚报。**虚报一：采用率冒充有效性**——"被多少工具支持"与"用起来到底好不好"是两个问题；行业盘点显示截至 2026-09 仅 3 家公布 LongMemEval 分数，Mem0、Letta 均未公布——沉默不是差评证据，也不是好评证据（S-lme-scores）。**虚报二：数字口径混用**——相对基线提升与绝对分不可直接比较，模型与配置还各不相同（S-zep）。

**权威对照**：LongMemEval 提供行业唯一公共基准，并公开"完美检索仍会答错"的阅读阶段失败分析——支撑"检索好≠答得好"（S-longmemeval）。本基准差异：把"须预注册、样本量须复算、口径须同轴"定为对所有厂商一视同仁的强制条款。

**起草方证据**：ab_preregistration.json 冻结（δ=0.15 / σ=0.5 / n=175/组 / 双盲评分 / 防 p-hacking）+ ab_sampler.py 每日采样。

### S4 · 行为序列监控 —— "越聊越笨"不是变笨，是走神

**费曼**：AI 长时间干活会"越干越糊涂"，业界曾以为它变笨了。其实它像长跑脱水的运动员：**不是能力没了，是节奏乱了**——反反复复做同一件事、改来改去忘了测。所以别盯着"感觉它笨了"，要给它戴运动手环：把行为编码成信号（探索/执行/规划/验证），机器盯基序，异常拉三色灯。

**缘由**：防**策略漂移误诊与漏诊**。权威旁证：LangGraph 官方文档承认长上下文 LLM 会被"陈旧或离题内容分心，即使窗口放得下也表现变差"（S-langgraph）；LongMemEval 实测 Oracle→S 变体掉分 30-60%，结论"信息在场但模型用不好——不是窗口长度问题，是注意力问题"（S-longmemeval）。

**权威对照**：MemGPT 用中断机制处理**上下文压力**（S-memgpt）——资源维度；本条款监控**行为模式**维度（序列基序），两者正交。行业无公开的行为序列三态监控器。**首创条款**。

**起草方证据**：behavior_governor.py 三态实测：真实轨迹检出"5 连改不测"🟡 / 恶化形态 🔴（验证率 0%）/ 健康形态 🟢。

### S5 · 修正闭环 —— 交付以"用户确认"收口，报错不罚、隐瞒才罚

**费曼**：活儿干没干完，**不是干活的人说了算，是用的人说了算**——他点头才算收口。配套一条铁规矩：主动报告错误的不罚，瞒报的才追责。因为如果报错要挨打，下次没人报错，错就藏在记忆里越藏越深。

**缘由**：防**假收口**与**沉默失败**。假收口与 T5/S2 同源（自报不可信），故收口标准必须外置到用户确认；沉默失败是记忆系统特有风险——坏记忆不报错，只在第 N 次检索时悄悄污染答案，等发现时已复利多轮。无惩罚报告与行业安全实践（blameless postmortem）同构；瞒报事故直接触发 T5 双倍记账。

**权威对照**：LongMemEval 的拒答能力测试是单点能力；本条款把它扩展为**全流程闭环**：立案意图 → 行为对账（S2）→ 用户确认收口 → 负反馈棘轮（同型不二犯）。

**起草方证据**：five_process_gate.py 4/4 断言 + 数量闸三态门。

## 6 · 实证案例（结论层）

- **案例 A（T1+T5）**：自检工具曾抓出"每流程只剩末项"的覆盖键 bug——被测试拦截未交付，不计台账；已交付的解析丢块入账（首宗 −2），同型复发双倍记 −4。台账区分"被闸拦住的"与"漏网的"。
- **案例 B（T 系条款）**：裁剪器在真实互联网页面遇到四个坑（根标签功能开关、void 标签跳过区、文档拆子页、正文藏 JSON）——全部只存在于真实页面，合成基准零命中。合成环境全对 ≠ 真实环境能用。
- **案例 C（T3）**：一次完整对外发表走全流程：发表前逐问审查 → 人工审批 → 授权通道推送 → commit 归属实勘。不可逆闸全程在环。
- **案例 D（S4）**：两个独立长会话样本显示：追问式头脑风暴 3-4 轮真实收益归零。行为编码监控把"换着花样复读"变成机器可检出的基序，而非依赖模型自我意识。
- **案例 E（S3）**：合作方声明"A/B 实验每组 128 个任务"，按其自设参数（δ=0.15、σ=0.5、α=0.05、power=0.80）复算正确值为 **175/组，偏低 27%**——样本不足将导致实验白跑。厂商数字必须复算。

## 7 · 五大原创主张

1. **标准即代码（Doc-from-Tests）**：条款由符合度测试反向生成——没有测试的条款根本进不了文档，文档永不与系统两张皮。
2. **遗忘经济学（NMR 负记忆率）**：全行业在比谁记得多，没人管"忘得好不好"。NMR = 坏记忆被读取占比 × 误导成本，把记忆质量从感觉变成钱。第一个把"遗忘质量"标准化的框架，榜单见 `leaderboard/`。
3. **记忆出处审计链**：每条记忆写入即入哈希链，篡改必断链，可回放任意时间点——"某天它相信什么"可以逐条举证。
4. **记忆可携协议 AMTF**：AI 版 GDPR 第 20 条。用户换 Agent 平台不必失忆归零——导出格式 = 内容 + 时效 + 溯源 + 置信度，缺字段显式留空禁静默补值。
5. **毒样本准入认证**：学界已证明记忆投毒可高成功率攻破（MINJA 实测注入成功率 98.2%，S-mpbench 关联研究）；本基准补的是防御侧"准入闸"——企业记忆写入前的最后一道安检，且可第三方复验。与攻击研究互补，不自称首创 benchmark。
